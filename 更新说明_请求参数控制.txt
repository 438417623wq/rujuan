--------------------------------------------------------------------------------
一、做了什么
--------------------------------------------------------------------------------

1. 采样参数（留空 = 不发送，默认行为与改动前完全一致）
   temperature / top_p / top_k / max_tokens / presence_penalty / frequency_penalty

2. 思考（推理）控制 —— 5 档模式
   auto   不发送任何思考参数（默认）
   off    尽力关闭
   on     开启
   effort 指定力度：最低 / 低 / 中 / 高 / 最高
   custom 自己写 body（不代管）

   另有「隐藏思考内容」开关：即使后端强行思考，也不把思考正文渲染进对话。

3. 自定义请求体（两框，对标酒馆）
   合并框 extraBody   —— JSON，或逐行 key: value；值尝试 JSON.parse 以保留数字/布尔
   删除框 excludeBody —— 一行一条，支持点号路径，如 thinking、reasoning.effort

4. 自定义请求头（两框）
   合并框 extraHeaders   —— 每行 Name: Value，或 JSON
   删除框 excludeHeaders —— 一行一条，如 Authorization

5. ★预览最终请求★（API 方案编辑器里）
   弹出实际会发出的 URL / headers / body（密钥已脱敏）。
   配置到底有没有生效，看一眼就知道，不用再猜。

二、各家的思考参数映射
--------------------------------------------------------------------------------

  Claude        off → thinking.type=disabled；力度 → thinking.budget_tokens
  Google 2.5    off → generationConfig.thinkingConfig.thinkingBudget
                ★Pro 系关不掉，官方最低 128；Flash / Lite 才能归零 0★
  Google 3.x    改用 generationConfig.thinkingConfig.thinkingLevel
  OpenAI o 系   reasoning_effort = minimal/low/medium/high
                GPT-5.4+ 的「off」映射为 none（这才是真正禁用）
  GLM / Kimi    thinking.type = disabled / enabled（不支持力度）
  MiMo          沿用原有 thinking.type 逻辑

  ⓘ 多数后端的推理无法被真正关闭，「关闭」是尽力而为。关不掉时请勾选「隐藏思考内容」。

--------------------------------------------------------------------------------
三、实现中踩到的两个坑（已修正）
--------------------------------------------------------------------------------

坑 1：采样参数在不同协议下的「落点」和「名字」不一样
  OpenAI / Claude  顶层 temperature / max_tokens / top_k
  Google           generationConfig.temperature / maxOutputTokens / topK

  如果按扁平字段名统一注入，Google 那边会被塞进三个无效的顶层字段，
  请求看起来「发出去了」，参数却没生效，且没有任何报错。
  修法：采样参数统一用点号路径表示，写入时两端各有一个 setPath 按路径落值。

坑 2：Google 的 off 不能一律给 thinkingBudget: 0
  Gemini 2.5 Pro 无法关闭思考（官方硬限制最低 128），给 0 会报错。
  修法：加 _googleBudgetFloor(model)，Pro 系下限 128、Flash/Lite 下限 0。

坑 3（安卓侧）：new JSONObject(String) 抛受检异常 JSONException，编译不过。
  修法：改成手工遍历键复制。

--------------------------------------------------------------------------------
四、双通道约束（重要，后续改动必须遵守）
--------------------------------------------------------------------------------

安卓 APK 的流式请求走原生 Java（NativeAiStreamService.java），
它自己重新拼了一遍请求体 —— 任何请求参数的改动必须 JS + Java 各写一遍。

本次采用的架构：**provider 映射策略全部留在 JS**，算好的扁平值（含点号路径）
通过 payload.requestParams 传给原生，Java 只负责「照单执行」：
  - sampler        采样参数（键可能是点号路径）
  - thinking       思考参数
  - extraBody      合并进 body
  - excludeBody    按路径删除
  - extraHeaders   合并进 headers
  - excludeHeaders 删除默认头

这样只有一处映射表，两端不会各自漂移。

--------------------------------------------------------------------------------
五、安全黑名单（硬编码，不可覆盖 / 不可删除）
--------------------------------------------------------------------------------

  messages, system, contents, stream

  前三个是对话内容本身，删了或覆盖了请求结构直接崩；
  stream 被改成 false 会导致前端拿不到 SSE，表现为「一直转圈 / 卡住不动」。
